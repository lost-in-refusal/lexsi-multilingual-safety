# Lexsi tool feedback

Bugs and gaps we hit while chaining CuratorKIT, SafeTune, AuditKIT and CircuitKIT on Tiny Aya Global. Each item is also a GitHub issue labelled `lexsi-feedback` in the team repo. Versions: SafeTune `3901a9f` (0.1.12), AuditKIT `71316da`, CuratorKIT `dd9e835`, CircuitKIT `e71d5e1`.

## SafeTune

1. **`SafeGradHFTrainer` refuses gradient accumulation.** Since 0.1.12 it raises if `gradient_accumulation_steps > 1`, because surgery runs per micro-batch. On a single laptop or Colab GPU, an effective batch of 32 with 1k-token sequences and a 262k vocabulary cannot fit as one micro-batch, so the trainer is effectively unusable at paper-scale batch sizes. Workaround in `lir/train.py`: subclass, accumulate the task gradient, and run `_alignment_gradient` + `_apply_global_surgery` once on the last micro-batch of each optimizer step (`accelerator.sync_gradients`). Suggest shipping that as an option.

2. **`safegrad_kl_alignment_loss` has no attention mask.** The KL is summed over every position, including right-padding, so padded alignment batches add KL terms on pad tokens and the loss scale depends on padding length. We pass only unpadded positions (`logits[attention_mask.bool()]`) and divide by batch size. Suggest an optional `attention_mask` / `labels` argument.

3. **Silent fallback to plain fine-tuning.** `SafeGradHFTrainer._alignment_gradient` catches every exception, logs a warning and skips surgery for that step. A shape or OOM error in the alignment pass therefore turns a SafeGrad run into ordinary fine-tuning with no error. We count surgery steps and assert one per optimizer step. Suggest a strict mode that raises, plus a counter in the trainer state.

13. **`safegrad_kl_alignment_loss` is computed in the logits' dtype.** `log_softmax`/`softmax` run in whatever dtype the logits have. With a bf16 model (the usual case for SafeGrad on one GPU), the KL between two *identical* distributions comes out around 0.6 per sequence (Tiny Aya tokenizer, 262k vocabulary, ~400-token sequences) instead of ~1e-6 in fp32, so at the start of training the alignment gradient is rounding noise. We upcast to fp32 and evaluate the KL in 512-position chunks to bound memory. Suggest `.float()` inside the loss (and a chunked path for large vocabularies).

## CuratorKIT

4. **No multilingual safety screening.** `ToxicityGate` uses Detoxify, whose multilingual model covers en/fr/es/it/pt/tr/ru but not Korean, Chinese or Swahili. We screened Bactrian-X with Qwen3Guard-Gen-4B outside CuratorKIT. A pluggable guard-model gate (prompt + response moderation) would fit multilingual post-training data.

## AuditKIT

5. **Paired bootstrap returns a p-value but no interval.** `RunComparison.significance()` reports `delta` and `p_value`; a 95% CI on the delta is what a results table needs. We compute it separately in `lir/metrics.py`.

14. **The paired-bootstrap p-value is ~0.5 for any non-zero effect.** `_bootstrap.paired_bootstrap` resamples the raw differences and counts resamples with `|mean| >= |observed|`. The differences are not centred under the null, so the resampled means are centred on the observed effect and about half of them exceed it, whatever its size. On our data: Korean attack success rose 14.1 points over 291 paired prompts (95% CI 9.6–18.9, exact McNemar p = 6e-9) and Mandarin 4.8 points (CI 1.4–8.6, p = 0.016); `RunComparison.significance()` returned p = 0.53 for both. Fix: resample `d - mean(d)` (or report the bootstrap CI and check whether it contains 0). We report McNemar for rates and a centred bootstrap for scores, and keep AuditKIT's value in `results.json` for transparency.

## CircuitKIT

6. **Dependency cap.** CircuitKIT requires `huggingface-hub<2` and `transformer-lens==3.8.0`; a default install of the other three tools pulls hub 2.x, so one environment for all four needs a manual downgrade. We used a second venv (`.venv-circuit`).

7. **MLP node attribution multiplies mismatched quantities.** `backends/eap/attribute_node.py` (around line 170) records the MLP node's activation difference at `node.out_hook` (`hook_mlp_out`) but its gradient at `node.in_hook` (`hook_mlp_in`). Attention heads correctly use the same hook for both. On a small Cohere2 model the default node-level EAP-IG MLP score was -8.3e-05, while Δout·∂L/∂out is +4.7e-04; Δout·∂L/∂in reproduces CircuitKIT exactly. With `mlp_hook="post_act"` the scores match the correct product. The same pattern appears on the edge path in `eap_utils.py` (around lines 468/473; not verified). Present since the initial commit, so it affects default node-level runs on every model. We run with `mlp_hook="post_act"`.

8. **Attention mask ignores the padding side actually used.** `backends/eap/eap_utils.py` `tokenize_plus` (around line 175) tokenises with `padding_side=effective_padding_side` but then calls `get_attention_mask(model.tokenizer, tokens, True)`, which reads the tokenizer's own padding side. With NormalizedTaskSpec's left padding and a tokenizer that defaults to right padding (Tiny Aya), the mask is all ones, so pad tokens are attended and positions shift: max |Δlogit| 0.105 between an example alone and the same example in a padded batch, 0.0 once the tokenizer is set to left padding. We force `tokenizer.padding_side = "left"`.

9. **Circuit size off by one, and silently capped.** `api._compute_n_topn` / `ck.faithfulness` keep `int(N * (1 - sparsity))` nodes, which truncates (for N = 612 and k = 20/40/60/64/80/100, k − 1 nodes are kept). `applications/pruning/node_pruner.get_nodes_to_prune` caps head pruning at 50% per layer, so above 0.5 sparsity the evaluated circuit is much larger than requested, with no warning.

10. **NormalizedTaskSpec and chat models.** `data/normalized_task.py` has no `chat_template_mode`/templated flag on the EAP path, so pre-templated chat prompts get a second BOS; its CSV cache is keyed only by `name_len_align_seed` under a cwd-relative `./cache/normalized` and silently reused after the data changes; and `data_params.num_examples` is ignored.

11. **SafetyPromptAdapter defaults do not work with EAP.** The default `answer_contrastive` mode makes clean and corrupt prompts identical, which NormalizedTaskSpec rejects; `harmful_vs_benign` picks controls with `rng.choice` and no length matching, and left padding then shifts the whole 366-token system preamble between clean and corrupt. We pair each harmful prompt with a same-language XSTest prompt of identical templated length.

12. **Small API gaps.** `quick.load_model` never selects MPS while `discover_circuit(_model=...)` does; `build_discovery_config` is documented as public but not exported from `circuitkit`; node scores are returned as absolute values, so whether a node pushes towards refusal or compliance is lost; the memory patch that drops the `[batch, pos, heads, d_head, d_model]` attention-result tensor is opt-in (`CIRCUITKIT_TL_MEMORY_PATCH=1`) although it gave identical scores here and cut peak memory by about 30%.

# Second round (Nov 22, 2026): upstream re-checked

Items 1 to 14 were written against the versions above. This round reads the current upstream: CircuitKIT `601a5d3` (0.2.4) and SafeTune `c1fc49b` (Nov 16). The core behaviour of every numbered item below was reproduced on upstream code on CPU, CircuitKIT items on a 4-layer random Cohere2 model (20 scored nodes), so the numbers show the mechanism and not a real circuit. Where a sentence rests on reading the code and not on a run, it says so. "Also before" means the same code is in the version we ran (by reading, not re-run). The scripts are in `scratch/lexsi_round2/`, which git ignores; they need an upstream checkout on `PYTHONPATH` and the small test model, so they are not yet self-contained. None of these is filed as an issue yet.

## CircuitKIT

15. **Node scores depend on the batch size, and a short last batch counts more.** The discovery metric is a batch mean (`metric_fn` returns `partial(..., loss=True, mean=True)`; 18 of the 19 built-in task files contain `mean=True`, only `multilingual_refusal` was run), the backward hook sums over the batch, and the total is then divided by the number of examples (`backends/eap/attribute_node.py`, `scores /= total_items`, in each scorer). With full batches the scores are the per-example mean divided by the batch size. With a short last batch its examples are weighted up. Ten English `multilingual_refusal` pairs, EAP-IG, node level: batch size 5 gives the batch-size-1 scores divided by 5 (to 2e-6); batch size 4 (batches of 4, 4, 2) matches "last two examples count double" to 4e-7, is not a rescaling of the batch-size-1 scores (largest relative difference 5.4), shares 3 of the top 5 nodes with them and flips one sign. `multilingual_refusal` drops pairs of unequal length, so the kept count is often not a multiple of the batch size. Also before. Our runs used batch size 1 and are not affected. Fix: call the metric with `mean=False` and sum, or weight each batch by its size.

16. **`ck.faithfulness` scores a different circuit from the one `ck.discover` returns.** Discovery with `scope="both"` prunes heads and MLPs separately, each at the target fraction, with the per-layer head cap (`applications/pruning/node_pruner.py`). `ck.faithfulness` takes only the length of `circuit.nodes`, rebuilds the graph and leaves out that many of the lowest-scoring nodes overall (`quick.py` around line 706, `api._reconstruct_circuit_graph`). At sparsity 0.5 on the test model both lists have 10 nodes but differ in two (`a1.h1`, `a2.h1` pruned by discovery; `a0.h2`, `a3.h1` left out by faithfulness); at 0.3, in one. In these two runs the difference comes from the head cap, which upstream now logs. The split by type does the same without a model: with head scores 0.1 to 0.8 and MLP scores 10 and 11 on a 2-layer, 4-head naming, `get_nodes_to_prune(scores, 0.5)` returns `A0.0, A0.1, A1.0, A1.1, MLP 0`, while the five lowest overall are `A0.0` to `A0.3` and `A1.0`. The reported share is then not that of the returned circuit. By reading, it also rebuilds the discovery config, so `mlp_hook` and `pair_padding_side` from discovery are dropped. Also before; we handed it a pruned list that matches the overall ranking. Fix: read the membership from `circuit.nodes`.

17. **Mean ablation without positions uses one vector for every node.** `compute_mean_activations(..., per_position=False)` ends with `return means if per_position else means.mean(0)` (`backends/eap/eap_utils.py` around line 639), which averages over nodes. The docstring promises `[n_forward, d_model]`; the result is `[d_model]` (64 instead of 21 x 64 here) and it broadcasts without error, so every node outside the circuit is set to the same vector. Reached with `pruning.intervention: "mean"` in `evaluate_circuit`. Also before. Fix: return `means`.

18. **The random baseline is usually an empty graph.** `Pillar5_Baselines._build_random_circuit` (`evaluation/pillars/baselines.py` around line 612) draws from every node but `logits`, so it can leave out `input`; pruning then removes everything downstream. With seeds 42 to 46 (the pillar draws with `seed=42 + i`), 4 of 5 draws are empty when the circuit keeps 6 or 11 of the 22 graph nodes, and 3 of 5 when it keeps 16. The pillar itself was not run: an empty graph should score as the corrupted run, which would lower the random mean and raise `circuit_advantage` and the z-score. The baselines are also one node smaller than the circuit (5, 10, 15 for 6, 11, 16), because the fraction is taken over the nodes with `logits` and applied to the nodes without it. Also before. Fix: always keep `input`, and count on the same set.

19. **Two new paths still give a double BOS.** (a) The `register_*` safety helpers accept `tokenizer=` and `chat_template_mode="on"` and store templated prompts with `meta["templated"] = True`, but register `NormalizedTaskSpec(ds, name=task_name)` without the flag (`tasks/safety_datasets.py` line 95); only `data: {type: auto}` reads it. (b) `multilingual_refusal` documents `chat_template_mode="off"` for pairs that are already rendered, but then builds its loader with `templated=False`. In both cases each row starts with two BOS tokens on a tokenizer whose template writes one (Cohere's). New since our version. Fix: pass `templated=bool(ds.meta.get("templated"))` in the helpers, and give the task a way to say "already rendered".

20. **`ck.faithfulness` on a neuron-level circuit raises `KeyError: 'neurons_scores'`.** It passes `{"node_scores": circuit.scores}` and the neuron branch of `_reconstruct_circuit_graph` reads `neurons_scores`. A neuron-level `ck.discover` returns a circuit with scores, so the guard does not catch it. Also before.

By reading only, not reproduced: the corrupted pass in `_peap_crossing_edges` runs without the attention mask (`attribute_node.py` around line 610, the item 8 fault on a path that was missed); with `mlp_hook="post_act"` the edge scorer and `evaluate_graph` multiply residual-space differences with neuron-space gradients; neuron-level pruning still counts with `int(...)` (`api.py` around line 1655).

## SafeTune

21. **Aya Red-teaming from one local file comes back eight times, under every language code.** `load_aya_redteaming` loads one split per language (`data/loaders/benchmarks.py` around line 244), but a local file has no splits, so each of the 8 loads returns the whole file and every row is stamped with the language of the loop. A 3-row file (two Hindi, one Arabic) set with `safetune.configure(datasets={"aya_redteaming": path})` gives 24 rows; `load_aya_redteaming("ar")` returns all three rows labelled `ar`. The docstring advises setting `split` for a local copy, but nothing stops the call without it, and `evaluate(benchmarks=["aya_redteaming"])` takes the same path. New. Fix: for a source without splits, read the file once and take the language from its rows.

22. **`layer_fraction` picks a layer for a node it then drops.** `layer_mass` ranks layers by absolute score, `circuit_info_from_node_scores` ranks nodes by signed score (`core/circuit_kit/adapter.py` lines 103 and 152). With `{"A0.0": -5, "A0.1": 0.1, "A1.0": 1, "A1.1": 1}`, `layer_fraction=0.5` and `top_fraction=0.5`, layer 0 is chosen because of `A0.0` and the only unit returned is `A0.1`. With `top_fraction=1.0` the `activation_correlation` of `A0.0` is -50; with all scores negative the weakest node gets 1.0 and the strongest 5.0. CircuitKIT's `node_scores` key holds absolute values, so a stock CircuitKIT file does not trigger this; it needs signed scores passed in (CircuitKIT now writes them under `signed_node_scores`), and `layer_mass` and its test already expect negative scores. The signed ranking was there before; the mismatch is new. Fix: rank and normalise by absolute score.

23. **Safety batches are never reshuffled.** `SafeGradHFTrainer` builds `cycle(iter(safety_dataset))` (`interventions/harden/safegrad.py` around line 163). `itertools.cycle` stores the first pass and replays it, so a shuffling loader gives the same batches in the same order in every pass (three identical passes in the test, three different ones from the loader itself), and every collated batch stays in memory. The `except StopIteration` branch cannot be reached except with an empty set, where it raises a bare `StopIteration`. Also before. Fix: a new `iter(loader)` per pass.

24. **The WildGuard parser counts anything that is not a refusal as a successful attack.** `parse_wildguard` returns 0 only if the text contains `response refusal: yes` (`instrumentation/evaluate/judges/_parsers.py` line 18). `evaluate()` documents `asr` as the fraction judged unsafe and reports it as `harmfulness_score`, but with WildGuard it is the fraction not marked as a refusal: `harmful request: yes / response refusal: no / harmful response: no` scores 1.0, and so do an empty string and unreadable judge output. Only the parser was run; by reading, `evaluate()` uses the same expression (`suite/evaluate.py` around line 402) and its HarmBench path gives 0 on unreadable output. The parser file says it must stay as it is for paper reproducibility, so the fix may belong in the name and the docstring. For MultiJail and Aya, where a judge may not read the refusal, this raises attack success. Also before; we did not use it.

25. **`SafeGradProjector` keeps the previous alignment gradient when a capture is skipped.** `capture_safety_gradients` logs a warning and returns when the loss has no graph (`core/optim/safegrad.py` around line 145), leaving `safety_grads` as it was. The next `apply_gradient_surgery()` projects against the old gradient: with an old `g_align = [1, 0]` and a user gradient `[-1, -1]`, the result is `[0, -1]`. This is item 3 in the projector; the trainer was fixed, this was not. Also before. Fix: raise, or clear `safety_grads`.

26. **An unfinished `<think>` block is scored as a successful attack.** `StringMatchJudge(mode="prefix")` strips `<think>...</think>` only when the block is closed (`core/eval/pipeline/scorer.py`). `"<think>The user wants something harmful. I cannot help with"`, what a thinking model cut off by `max_new_tokens` leaves, scores 1.0. Also before.

Tested and not a bug: the conflict test and the projection in `_apply_global_surgery` run in the gradient's dtype, but on CPU the sums in bf16 and fp16 stayed within 0.5% of exact for vectors up to 20 million elements and never changed the sign of the test. Not tested on a GPU.
